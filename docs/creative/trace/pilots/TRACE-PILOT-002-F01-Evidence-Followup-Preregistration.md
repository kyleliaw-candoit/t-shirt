## Evidence coding before recipe matching

Code results in query/result order. Record relevance, firsthand versus summary, the supported claim, a brief exact excerpt, URL and comment/post locator if available, and uncertainty. Use distinct authors as evidence units; duplicate/syndicated statements are one unit. Unknown author independence cannot satisfy the two-author requirement. Multiple authors in one thread may corroborate existence but remain one discussion context; explicitly flag that clustering.

For each identity, retain at most two input records:
- PREFERENCE: the first directly expressed voluntary enjoyment or valued modest outcome encountered, followed by the first independent author within the fixed pool explicitly supporting the same bounded claim. A statement about hardship, obligation or tolerating failure does not establish willing preference. Do not add “low status” unless supported; that interpretive contrast belongs in later recipe matching.
- ACTIVITY: the first participant-used verb phrase describing a concrete recurring activity, followed by the first independent author in the fixed pool using the same phrase or a minimal grammatical variant for that activity. Do not select a later phrase because it yields a better pun. A noun, identity label or metaphor without an ordinary activity does not qualify.

A first candidate lacking corroboration remains SINGLE-SOURCE; do not replace it with a later, easier candidate. Missing or inaccessible evidence stays MISSING/BLOCKED. Two statements support existence in these records, not population frequency or universal community identity. Cross-query evidence may corroborate the first candidate within the same R-ID; preserve every originating result position.

Threshold statuses: READY (two independently authored direct statements), SINGLE-SOURCE, MISSING, BLOCKED. The same person in different threads is not independent. Do not infer usernames, dates, wording or behaviors from inaccessible text.
